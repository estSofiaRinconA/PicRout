CÓMO SE UTILIZA ESTA GUÍA
-------------------------
1. Levanta el backend (sección 0).
2. Abre http://127.0.0.1:8000/docs (Swagger UI).
3. Sigue los pasos en orden (1 → 5).
4. Marca cada casilla [ ] cuando el resultado coincida con lo esperado.
5. Si algo falla, anota el código HTTP y el mensaje de error.
6. Al final, usa el resumen para decidir si el paso está aprobado.


================================================================================
0. PREPARAR EL ENTORNO
================================================================================

Comandos (desde la carpeta PicRout/backend):

  python -m venv venv

  # Windows:
  venv\Scripts\activate

  # macOS / Linux:
  source venv/bin/activate

  pip install -r requirements.txt
  # Si bcrypt da error: pip install "bcrypt==4.0.1"

  copy .env.example .env          # Windows
  # cp .env.example .env          # macOS / Linux

  uvicorn App.main:app --reload --host 127.0.0.1 --port 8000

Comprobar:
  - Navegador: http://127.0.0.1:8000/health
  - Debe responder: {"status":"ok"}
  - Documentación: http://127.0.0.1:8000/docs

En Swagger:
  - Tras el login, pulsa "Authorize".
  - Escribe: Bearer <tu_access_token>
  - Confirma. Todos los endpoints protegidos usarán ese token.

1. AUTENTICACIÓN (PASO 1)
================================================================================

1.1 Registro
------------
Endpoint: POST /auth/register
Body (JSON):
{
  "email": "sofia@picrout.app",
  "username": "sofia",
  "password": "ClaveSegura123",
  "display_name": "Sofía Rincón"
}

Esperado: 201, access_token y datos del usuario.
[ ] OK

Guarda el access_token. Lo usarás en Authorize.


1.2 Login con correo
--------------------
Endpoint: POST /auth/login
Body:
{
  "identifier": "sofia@picrout.app",
  "password": "ClaveSegura123"
}

Esperado: 200 + access_token
[ ] OK


1.3 Login con username
----------------------
Body:
{
  "identifier": "sofia",
  "password": "ClaveSegura123"
}

Esperado: 200 + access_token
[ ] OK


1.4 Login con contraseña incorrecta
-----------------------------------
Body:
{
  "identifier": "sofia",
  "password": "mala"
}

Esperado: 401
[ ] OK


1.5 Perfil — consultar
----------------------
Authorize con el token.
Endpoint: GET /auth/me

Esperado: 200, username = sofia
[ ] OK


1.6 Perfil — actualizar
-----------------------
Endpoint: PUT /auth/me
Body:
{
  "display_name": "Sofía R.",
  "bio": "Probando PicRout",
  "theme": "dark",
  "color": "#10B981"
}

Esperado: 200, bio y color actualizados
[ ] OK


1.7 Recuperación de contraseña (OTP)
------------------------------------
a) POST /auth/forgot-password
Body:
{ "email": "sofia@picrout.app" }

Esperado: 200, mensaje genérico.
En la CONSOLA del servidor debe aparecer el código de 6 dígitos, por ejemplo:
  [DEV] OTP para sofia@picrout.app: 649488
[ ] OK (mensaje API)
[ ] OK (código visible en consola)

b) POST /auth/reset-password
Body:
{
  "email": "sofia@picrout.app",
  "code": "649488",
  "new_password": "NuevaClave456"
}

Esperado: 200, contraseña actualizada
[ ] OK

c) Login con la nueva contraseña
[ ] OK

d) Reutilizar el mismo código OTP
Esperado: 400 (código de un solo uso)
[ ] OK


1.8 Google Sign-In (estructura)
-------------------------------
POST /auth/google
Body: { "id_token": "cualquier_texto" }

Esperado: 501 (aún no implementado del todo)
[ ] OK


1.9 Email duplicado
-------------------
POST /auth/register con el mismo email otra vez.

Esperado: 400
[ ] OK

---------------------

  "duration_minutes": 5
}

Esperado: 201
  verification_method ≈ single_photo
  base_points bajos (aprox. 5–8)

Anota routine_id: ________

Esperado: 201, verification_method ≈ quiz, puntos altos
[ ] OK
Anota routine_id: ________


2.4 Listar rutinas
------------------
GET /routines

Esperado: 200, al menos 3 rutinas
[ ] OK


2.5 Ocurrencias de hoy
----------------------
GET /routines/today

Esperado: 200, 3 ocurrencias en estado "pendiente"
[ ] OK
Anota occurrence_id de cada una:
  - Hacer la cama: ________

  - Estudiar algoritmos: ________

-----------------
GET /routines/streak

Esperado: current_streak = 0, points = 0 (o solo puntos si marcaste algo antes)

[ ] OK

================================================================================
4. VERIFICACIÓN COMPLETA: QUIZ, FOTO ÚNICA Y ANTES/DESPUÉS
================================================================================

4.1 Iniciar verificación (común a los tres)
-------------------------------------------
POST /verification/{occurrence_id}/start

Esperado: 201
  method = single_photo | before_after | quiz
  Si es quiz: quiz_questions con 3 preguntas (sin correct_index)
  La ocurrencia pasa a "falta_verificacion"
[ ] OK start foto única
[ ] OK start before_after
[ ] OK start quiz

Anota attempt_id de cada una:
  - single_photo: ________
  - before_after: ________
  - quiz: ________


4.2 Caso FOTO ÚNICA
-------------------
POST /verification/attempts/{attempt_id}/photo
Tipo: multipart/form-data
Campo: photo = archivo .jpg / .png / .webp real (mayor a 1 KB)

En Swagger: Try it out → elige el archivo en "photo" → Execute.

Esperado: 200
  attempt.status = passed (si el archivo es válido)
  occurrence_status = completada
  puntos actualizados
[ ] OK

Negativos:
  - Sin archivo → 400
  - Archivo vacío o muy pequeño → 400
  - Extensión no permitida (.txt) → 400
[ ] OK negativos


4.3 Caso ANTES / DESPUÉS
------------------------
POST /verification/attempts/{attempt_id}/photo
Campos:
  photo_before = imagen 1
  photo_after  = imagen 2

Esperado: 200, status = passed, ocurrencia completada
[ ] OK

Negativo: enviar solo una de las dos → 400
[ ] OK negativo


4.4 Caso QUIZ
-------------
Tras el start, copia las preguntas de la respuesta.

POST /verification/attempts/{attempt_id}/quiz
Body ejemplo:
{
  "answers": {
    "0": 1,
    "1": 0,
    "2": 2
  }
}

(0 = primera opción de la pregunta 0, etc.)

Esperado:
  - Si aciertas ≥ 60 % → status = passed, ocurrencia completada
  - Si fallas → status = failed
[ ] OK quiz (al menos un intento)

GET /verification/attempts/{attempt_id}
Revisa quiz_score y result_message
[ ] OK


4.5 Cómo subir fotos con curl (alternativa a Swagger)
-----------------------------------------------------
Foto única:
  curl -X POST "http://127.0.0.1:8000/verification/attempts/1/photo" \
    -H "Authorization: Bearer TU_TOKEN" \
    -F "photo=@C:/ruta/foto.jpg"

Antes y después:
  curl -X POST "http://127.0.0.1:8000/verification/attempts/2/photo" \
    -H "Authorization: Bearer TU_TOKEN" \
    -F "photo_before=@C:/ruta/antes.jpg" \
    -F "photo_after=@C:/ruta/despues.jpg"

5. RACHA DEL DÍA COMPLETO
================================================================================

Cuando TODAS las ocurrencias de hoy estén en "completada":

1) GET /routines/today
   → completed debe ser igual al total de ocurrencias
   [ ] OK

2) GET /routines/streak
   o POST /routines/evaluate-today

Esperado:
  - current_streak aumenta en 1
  - se suman puntos de bonus por racha
  - si evalúas otra vez el mismo día, NO vuelve a sumar (idempotencia)
[ ] OK racha
[ ] OK no dobla racha al reevaluar

================================================================================
7. NOTAS IMPORTANTES
================================================================================

- Días de la semana: 0 = Lunes, 1 = Martes, …, 6 = Domingo.
- Sin API key de IA (GROQ / GEMINI / XAI), el análisis usa heurísticas locales
  y las fotos se validan por tipo, tamaño y existencia (no visión profunda).
- Con SMTP vacío, el OTP solo se imprime en la consola del backend (modo dev).
- Fotos permitidas: JPEG, PNG, WebP. Máximo según MAX_PHOTO_SIZE_MB en .env
  (por defecto 10 MB). Mínimo aproximado: no vacías (> 1 KB).
- Las fotos se guardan en STORAGE_PATH (ver .env), subcarpeta verifications/.
- Token JWT: en Swagger → Authorize → "Bearer <token>" (incluye la palabra Bearer).
